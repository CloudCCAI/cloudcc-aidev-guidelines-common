# 项目目标

`goals.md` 是项目目标、范围和成功标准的唯一事实源。

## 项目愿景

为 AI 智能体提供一套可复用、可校验、可跨会话恢复的项目状态与交付规范，让多智能体协作、异步多开发者并行交付、老项目接入和项目级技能约束都能落到仓库文件中。

## 当前范围

### In Scope Now

- 维护 `skill/SKILL.md`、`skill/STATE-MODEL.md`、catalog、references、模板、脚本、测试和示例的一致协议
- 通过 manifest 和逐文件状态提供可检测、可引导、可暂停恢复的 Greenfield/Brownfield 初始化
- 用开关独立控制项目状态、多人协作门禁和代码合并申请，只加载启用模块
- 以带用户名的个人 FEAT/TASK 序列和多工作流热索引支持多人、多聊天窗口并行
- 对已有 `.claw` 文件和旧全局 ID 保持非破坏性兼容，对新文件执行 v5 规则
- 提供项目经理门控授权、SSH challenge-response、assignment、平台评审和动态状态校验

### Out Of Scope Now

- 面向特定技术栈的业务模板
- 通用业务代码生成框架或应用脚手架
- 仓库内完整密码学签名/验签实现
- 未经用户明确请求的历史文件批量迁移

## 成功标准

| 维度 | 指标 | 目标值 |
|------|------|--------|
| 功能 | 初始化可恢复性 | manifest 能定位第一个未完成核心文件，并在确认后进入 ready |
| 质量 | 协议一致性 | catalog、协议、脚本、模板、示例和校验器保持同步 |
| 性能 | 启动成本 | 只加载 manifest、热索引和当前工作需要的温/冷资料 |
| 业务 | 多智能体可恢复性 | 新接手智能体能从仓库文件判断技能要求并继续推进 |
| 协作 | 异步并行可集成性 | 开发者能通过身份记录、任务授权、单任务状态和集成队列完成并行交付 |
| 管理 | 团队状态可视性 | 管理者能通过标准汇总脚本查看成员、任务、贡献和集成状态 |
| 安全 | 授权门禁可执行性 | 开发前和 CI 能检查开发者身份、任务授权、分支和文件范围 |
| 兼容 | 历史项目非破坏性 | legacy 项目不被自动改名、补字段或强制采用 v5 |

## 约束

- 时间约束：技能协议演进需要保持文档和脚本同步发布
- 技术约束：尽量使用仓库内现有 bash/python 工具，不引入重依赖
- 合规约束：项目级声明必须明确 GitHub 安装来源
- 安全约束：仓库文档不得保存管理者口令、开发者 token、私钥或可复用密钥
- 身份约束：Git author name/email 不能作为强身份依据，默认使用 Git 平台账号绑定和 SSH commit signing
- 资源约束：保持技能主体和示例文件简洁，避免上下文膨胀
